# renan/ui rules

A shadcn registry on Base UI. Rules come from the `frontend-design` and `animate` skills; read them before adding a component.

- **Tokens only.** Components read the shadcn theme vars and the layer-2 tokens in `registry/tokens.mjs`, never raw colors, sizes or durations. Run `pnpm registry:build` after changing tokens, components or themes (regenerates `registry.json`, `app/ds-tokens.css`, `public/r`).
- **Controls:** `h-control` / `-sm` / `-xs` / `-lg` and `rounded-control`. Small touch targets get `hit-area`.
- **Focus:** `focus-ring` (outline, 2px offset, `--ds-focus-ring`). Never a box-shadow ring; destructive variants set `[--ds-focus-ring:var(--destructive)]`.
- **Elevation:** one per role: `shadow-border` (cards), `shadow-popover` (menus, popovers, selects), `shadow-modal` (dialogs, sheets). Never a border plus a shadow on the same surface.
- **Motion:** `motion-press` on pressables, `motion-popover` / `motion-tooltip` / `motion-modal` / `motion-backdrop` on Base UI popups. Transitions only (no `animate-in` keyframes), `transform`/`opacity` only, never `transition-all`, never `scale(0)`. Reduced motion keeps fades, drops movement. Nothing animates on keyboard-shortcut actions.
- **States:** every control covers hover, focus-visible, active, disabled, loading (`Button loading`), invalid.
- **As few `useEffect`s as possible.** Use one only when there's no other way: subscribing to something outside React (a DOM/window event, a third-party store) with cleanup. Before writing one, reach for, in order:
  1. Derive during render (computed values, no state).
  2. CSS: data attributes, `group-*` / `has-*` variants, transitions (e.g. `Button` loading is pure CSS width animation).
  3. The event handler that caused the change (including writes to `document`).
  4. Adjust state during render when a prop changes (`if (prop && !state) setState(true)`).
  5. DOM events like `onTransitionEnd` / `onAnimationEnd` for "after the animation" logic, never `setTimeout` in an effect.
  6. `useSyncExternalStore` for external stores, a `key` to reset state.
  Never `setState` synchronously inside an effect, and never an effect to sync one piece of state from another.
- **Token CSS (`css` in `registry/tokens.mjs`):** shadcn's CSS writer handles only one nesting level inside `@utility`. Put `@media` at the top level and act through variables or plain selectors (see `hit-area`, `--ds-motion-scale`). Verify a change by installing `public/r/tokens.json` into a fresh project and building it.
- **Hotkeys** (`@tanstack/react-hotkeys`): actionable components take a `hotkey` prop (`Button`, `DropdownMenuItem`; `TooltipContent hotkey` only displays). Show shortcuts with `<Hotkey>` (never hand-written "⌘K"), set `aria-keyshortcuts` via `toAriaKeyShortcuts`, and press elements with `useHotkeyPress` so popups opened from the keyboard skip their motion. Prefer `Mod+…` or `Shift+…`; single letters only where no text input or menu typeahead competes.
- **Responsive overlays:** below 640px `Dialog` renders a swipeable `Drawer` (same tree, mode from context; `responsive={false}` opts out), `Popover` and `DropdownMenu` become bottom sheets via `max-sm:` classes plus `--ds-motion-y` / `--ds-motion-ease`, and on touch devices `Select` with `items` renders the native picker. Touch devices also get 44px controls (`--ds-control-h` under `pointer: coarse`). Detect viewport with `useMediaQuery` (`useSyncExternalStore`), never an effect.
- **Forms** (React Hook Form + zod): `useZodForm(schema)` (validates on blur, then live while invalid), `<Form form onSubmit>` (real `<form>`, blocks double submit, thrown errors become `<FormBanner>`), `<FormField name label render>` (label, `id`, `aria-invalid`, `aria-describedby`, error text), `<FormSubmit>` (never disabled while invalid; busy while submitting). Error copy says what's wrong and how to fix it. Pick inputs by option count: 2 → switch/radio, 3–7 → `Select`, 8+ or many values → `MultiSelect` / combobox.
- **Text wrapping:** base CSS sets `text-wrap: balance` on headings and `pretty` on `p, li, dd, figcaption, blockquote`. Don't set it on `*`. Put `data-streaming` on regions whose text changes per frame (AI streaming, live logs) so they use plain wrapping; very long text and code keep the default.
- **States:** loading regions use `<SkeletonGroup label="Loading …">` (skeletons shaped like the content, shown only after 200ms); empty regions use `Empty` with the variant that matches the cause (first use, no results + clear filters, no permission); failed regions use `<ErrorState onRetry>` per section; reversible actions run immediately with `toastUndo` instead of a confirm dialog.
- **Contrast:** `pnpm check:contrast` checks every theme (text 4.5:1, focus ring 3:1, light and dark); `--fix` nudges OKLCH lightness only. Run it after adding a tweakcn theme.
- **Worst-case data:** base CSS sets `overflow-wrap: anywhere` so long words never widen a card; user-entered labels in chips/badges truncate with a `title`. Popups that list options (`DropdownMenu`, `Select`) are at least the trigger's width and grow to fit, capped at `--available-width`. Rows in menus/selects/comboboxes are 36px (44px on touch). Before shipping a component, render it at 320px with a 50-char word, an empty value and CJK/Arabic text.
- **Composition:** before building a card, panel, dialog or palette, read `docs/COMPOSITION.md` and start from the closest example in `components/examples/` (`/examples` in the playground). Use `Panel`/`PanelCard`, `IconTile`, `Badge tone`, `DataList`, `TabsList variant="segmented"`, `Alert tone` and `Button variant="surface"` instead of one-off styling.
- **Checks before pushing:** `pnpm typecheck && pnpm lint && pnpm check:contrast && pnpm registry:build && pnpm build && pnpm audit:ui`. `audit:ui` (Playwright) runs every docs page (each component page included) and block demo at 320px and 1280px in light and dark, opens every select and dialog, and fails on icons off their label's center by more than 0.5px, horizontal overflow, select popups narrower than or offset from their trigger, unnamed icon-only buttons, console errors, and any axe-core WCAG 2.2 A/AA violation (desktop, light and dark). `AUDIT_SHARD=2/4` audits a quarter of the pages (CI runs four in parallel); `node scripts/axe-detail.mjs /path [rule]` prints the failing HTML for one page. Accessibility rules that bit us: soft destructive/status surfaces use `tone-*` (contrast-checked on card, page, muted and hovered rows), never the theme's raw `--destructive` on a tint; a control's accessible name contains its visible text (hide decorative key caps with `aria-hidden`); separators inside `list`/`listbox` are `aria-hidden`; 16px targets keep 24px clear around them. New pages go in its `PAGES` list. CI (`.github/workflows/ci.yml`) runs all of this plus a fresh-project install of the registry.
- **Blocks** (`components/blocks/<name>/`, published as `registry:block`): full screens built only from `components/ui`. Keep them router-agnostic (plain `<a>` or a `linkComponent` prop, `onNavigate`, `currentPath`) so they run in Next.js and Vite; put shareable view state in the URL with `hooks/use-url-state` (`useSyncExternalStore` + History API). Demo routes live in `app/blocks/` (the `(app)` group wraps pages in `AppShell`); add each new route to `ALL_PAGES` in `scripts/audit-ui.mjs`. With TanStack Table, memoize state derived from the URL by value: a new array each render re-triggers its auto-resets and loops.
- **Docs site** (`app/(site)`): `/` home, `/components` (sidebar and pages generated from `registry.json` + `registry/catalog.json`), `/blocks` (iframe previews at device widths, source tab), `/examples`, `/themes` (playground). Every `components/ui` file needs a catalog entry (group, title, description, notes) and a demo file `components/demos/<name>.tsx`; `registry:gen` fails without them, and the catalog description becomes the registry item's description. Demo files are Storybook CSF style: each `export function Name()` is one story (the first is the page's main preview), an optional `/** … */` above it becomes its description, and the code tab shows the story with only the imports and top-level helpers it uses, so keep stories self-contained and copyable. Don't use external images or network calls in demos (the audit fails on console errors).
- **Button content alignment:** `Button` always holds an empty spinner slot (it animates the loading width), so never `justify-between` a Button's children: the slot takes a share of the free space and shifts the label. Use `justify-start` and `ms-auto` on the trailing part (hotkey, chevron, count).
- **Charts:** series colors are `--ds-chart-1…8` (`fill-series-N`), the dataviz skill's categorical palette validated with its `validate_palette.js` on the light and dark card. Assign in order, never cycled; 2+ series get a legend, every chart a tooltip; one y-axis; bars ≤24px with 4px rounded ends; `isAnimationActive={false}` (no 1.5s entrance).
- **Tables:** pick by job. `DataTable` (search, filters, pages in the URL), `GroupedTable` (spreadsheet view: collapsible groups, calculation footer, floating bulk bar), `InfiniteTable` (cursor pagination for feeds and logs; `useCursorPages` has the `useInfiniteQuery` shape, reset it with a `key` when filters change). Pinned header, bands or footer need `border-separate border-spacing-0` and borders as inset shadows, and the scroll container must be the table's own `relative` div (an `overflow-x-auto` wrapper breaks `sticky top`; without `relative`, absolutely positioned descendants like `sr-only` text escape the clip and scroll the page). Full-height tables go in `AppShellContent fill` with `flex-1 min-h-0`, never a `calc(100dvh-…)` guess: only the table scrolls, never the window too. First-load skeletons fill the whole table and clip (no scrollbar). Infinite lists load ahead (`rootMargin` 600px), keep a "Load more" button for keyboard and screen readers, retry inline, and say when the end is reached. Row checkboxes are named after the row (`getRowLabel`), not its number.
- **Width-dependent layout inside blocks:** use container queries (`@container`, `@2xl/table:`), not viewport breakpoints: beside a sidebar, a tablet screen holds a phone-width table.
- **Resizable sidebars (DS standard):** every sidebar that resizes or collapses follows the app shell pattern (`variant="fade"`, the default): labels stay mounted; icons keep one position in both states (never `justify-center` there). The edge is a resize handle (drag, double-click, Enter, arrows); under 160px it settles to the icon rail. `motion` sets how labels leave: `ease-out` (snap, 0.16s fade, 0.4s width), `cascade` (drift left, fade top-down via `--i`), `scrub` (opacity follows the drag width). Timings live in `SIDEBAR_MOTION` as CSS variables. New sidebars (docs nav, settings sub-nav, inspector panels) reuse it rather than animating width with unmounting labels; `variant="classic"` exists only for the old rail.
- **Sample data:** the signed-in user is Renan Leonel (RL, renan@acme.dev). Everyone else gets common Brazilian names (Ana Souza, João Silva, Pedro Santos, Maria Oliveira, Lucas Costa, Beatriz Lima); use other people only when several users appear.
- **Values only known in the browser** (stored theme, locale, `toLocaleString` without a locale): render them after mount (`useSyncExternalStore`) or with a fixed locale (date-fns), or hydration fails.
- **Reordering:** use `Sortable` / `SortableItem` / `SortableHandle` (dnd-kit). It handles pointer and keyboard (Space, arrows, Space; Escape cancels), screen reader announcements (`getLabel`), the lift animation and reduced motion, and works inside dialogs (its keyboard sensor listens in the capture phase because overlays stop arrow keys). Chevrons on popup triggers turn 180° while open (`group-data-popup-open`), never swap icons.
